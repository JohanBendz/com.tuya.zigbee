## First implementation batch: #1026

Within the first batch, only `drivers/smart_remote_1_button_2/device.js` changes
device behavior.
It retains the exact `_TZ3000_ja5osu5g / TS004F` matcher, Homey driver ID,
capability list, settings and `smart_remote_1_button_2` Flow actions.

- Accept only endpoint-1 cluster-6 cluster-specific Tuya action command 0xFD,
  with a valid three-byte non-manufacturer ZCL header and one action byte.
- Map 0/1/2 to the existing oneClick/twoClicks/longPress values. Reject unknown
  actions and malformed/truncated/unverified frame forms as gestures.
- Support native Buffer and serialized Buffer input without mutating it.
- Preserve the captured ZCL dispatcher, receiver, metadata, return value and
  error behavior for all other traffic, including the standard OnOff command
  that follows each captured gesture. Consume a recognized gesture only once.
- Reinitialization must not stack wrappers; device deletion restores the
  original dispatcher only while this device's wrapper is still installed,
  and still invokes the SDK's listener/interval cleanup.
- No timer debounce, alternate-frame counter, new capability, battery
  implementation, manufacturer additions or shared-cluster changes.

The original #1026 captures are the concrete regression input. The new
`test/single-button-1026.test.js` exercises the actual driver with Homey/Zigbee
stubs: captured single/double/hold pairs for both Buffer representations,
invalid/unknown packets, ordinary ZCL traffic, rapid legitimate presses,
sequence wrap, hook lifecycle and failure propagation. The old source failed
eight of the nine tests; all nine pass after correction. This is automated
evidence only.

## Second implementation batch: #1438

Parent: `0be7fca64c358a57b95a236796e68f5a37a6a500` (merged PR #1536).
Only `drivers/fingerbot/device.js` changes runtime in this batch. The original
#1438 first-hand report establishes real alternating On/Off mechanical presses
at three-second Flow intervals for `_TZ3210_j4pdtz9v / TS0001` in click mode.
It does not establish equivalence for the other three manufacturers or the
TS0001_fingerbot alias, nor physical acceptance of our implementation.

- Enable the strategy only after Basic reads return that exact pair. Missing,
  unreadable or different identity keeps legacy command/suppression behavior.
- In configured click mode, serialize each request and wait for the existing
  2,000 ms minimum interval instead of dropping it. Each caller receives its
  own command result; failed commands reject without poisoning later requests.
- Choose the opposite of the last known boolean state; with no known state,
  start with Off as in the reporter's tested strategy. Read OnOff on startup
  for the exact identity, with a five-second timeout; fall back to stored state
  if the read fails. This read sends no On/Off command.
- Track boolean reports before the existing echo filter; a report arriving
  during a command takes precedence over its acknowledgement. Persist state
  under lastKnownFingerBotOnOff. Storage failure is logged, retains in-memory
  state and never automatically retries a possibly executed command.
- Keep the 3,500 ms local echo window, remote debounce and Flow IDs. Suppress
  echoes throughout an in-flight queued command and refresh the echo window
  after acknowledgement, including a slow response. Emit one local Flow
  after an acknowledged queued command, not one per echo report. Acknowledgement
  is not evidence of mechanical movement.
- Cancel waiting work on mode change, removal or reinitialization. Do not let
  old queued clicks force a subsequently selected switch/program mode. Reject new
  queued clicks while the mode write is pending. Preserve
  SDK cleanup when removed. Already sent Zigbee commands cannot be recalled.
- Other manufacturers and the model alias retain repeated-On and suppression.
  Switch/program onoff still passes both states through. The explicit Push
  action's existing mode-forcing behavior outside click mode is retained.
- No pairing/capability/settings/Flow manifest change, battery implementation,
  Tuya datapoint/protocol change or shared/light runtime change is included.

`test/fingerbot-1438.test.js` exercises the actual device source, actual Push
Flow listener and deterministic Homey timers. Nineteen cases cover three-second
repeats, queued rapid requests, delayed/rejected radio commands, reported/read/
stored state, persistence failure, variant/mode isolation and queue cancellation.
The initial fourteen cases produced twelve failures and two passes against the
parent source; all nineteen cases pass after the correction. This is automated
command/Flow evidence, not mechanical hardware evidence.
