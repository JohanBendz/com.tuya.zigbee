## PR #1535 source review

Reviewed unchanged head `5dd2e4301457220b9ba90cd081aa8ed8ba3df2c1`.
GitHub reported it mergeable at final inspection; the earlier transient conflict
notice was corrected. No Actions run was returned for that head during this
review. No CI success, code approval or real-device acceptance is inferred.

Two reproducible implementation blockers:

1. `setTargetTemperature()` changes Homey's target_temperature first, fires the
   Zigbee write without awaiting its outcome, catches/logs failure and resolves.
   In an isolated VM, a rejecting datapoint stub produced: request 22 C from
   20 C, method resolved, Homey value 22, one rejected write logged. This is a
   simulated transport failure, not hardware evidence. Define truthful pending/
   success/failure semantics for both UI and Flow, with a bounded queue/timeout
   strategy if needed for sleepy hardware.
2. `sendTuyaTime()` supplies `{payload}` without the required `payloadSize`.
   With the actual locked zigbee-clusters 2.4.1 ZCLStruct serializer, an eight-byte
   payload serialized length 0; explicitly providing payloadSize:8 produced 8.
   Match the explicit-length current app call and cover the wire shape.

Also reconcile the generated manifest/index and 0.4.1 candidate checks without
weakening immutable compatibility fixtures. DP15 is a reported window status,
while the app's shared window_open capability is settable: choose a read-only
representation for this new profile without changing installed thermostats.
Gate raw DP/time tracing and align cooldown documentation with the code's
20-second constant. Keep schedules out of the first scope; test negative
calibration, late/rejected writes, time bursts and each exact identity.

Primary reference checked: current [tuya.ts](https://github.com/Koenkk/zigbee-herdsman-converters/blob/master/src/devices/tuya.ts)
groups _TZE204_vjpaih9f and _TZE284_vjpaih9f as TS0601_thermostat_14,
with setpoint DP4 /10, temperature DP5 /10 and battery DP6. This corroborates
protocol intent; it does not prove either specimen works in our Homey driver.
